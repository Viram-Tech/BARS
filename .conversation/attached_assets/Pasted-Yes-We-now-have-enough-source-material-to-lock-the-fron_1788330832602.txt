### One extra instruction I strongly recommend adding to the coding agent

Before it writes the final UI, make it create a **`/design-system` or `/showcase` route** and implement the entire visual language there first. Make that page contain the typography scale, colour tokens, buttons, inputs, filters, source badges, verification badges, resource cards, organisation cards, metrics, tables, charts, assistant states, light/dark themes and responsive states.

That will prevent the agent from inventing 20 different styles across 20 pages.

The source material gives us a strong functional foundation: the homepage establishes the repository, ecosystem and 2030 mission; the repository establishes knowledge discovery and verification; and the directory establishes the stakeholder network.   

For the **first coding-agent run**, I would start with only:

**design system → global shell → homepage → repository → dashboard → directory → assistant shell**

and make those absolutely exceptional before expanding to the secondary screens.
